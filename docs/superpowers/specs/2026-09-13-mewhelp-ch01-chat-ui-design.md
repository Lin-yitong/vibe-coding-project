# MewHelp Ch01 — 像素风聊天界面设计

## 目标

为已完成的 Ch01 FastAPI 纯对话服务增加浏览器聊天界面。用户能创建或切换本浏览器内的会话，发送售后问题，看到客服 SSE 回复随 `delta` 实时增长，并在同一会话中继续追问。

## 范围与边界

- 新增 `MewHelp/frontend/`，使用 Vue 3、Vite、TypeScript 和原生 CSS。
- 对接既有 `POST /api/chat`，不修改其 API 契约。
- 不新增数据库、账户、持久化后端记忆、工具调用、Agent 循环或订单/物流查询。
- 不展示“调用工具”徽标，不伪造订单状态、物流、退款、赔付或平台规则。
- 浏览器刷新后可丢失前端会话列表；后端内存会话仍按 Ch01 原有进程生命周期保存。

## 视觉与布局

风格参照确认的图片：暖橙色顶栏、浅米色内容区、深紫黑粗描边、轻微像素/网格背景与方正按钮。桌面端主体为双栏布局：

```text
┌──────────── 会话记录 ────────────┬──────────── 小喵 · 智能客服 ────────────┐
│  会话卡片：标题 + 最后一条摘要     │  像素头像、ONLINE 状态、［＋ 新对话］    │
│  当前会话使用橙色边框突出          ├─────────────────────────────────────────┤
│                                    │  用户消息气泡（右、珊瑚橙）              │
│                                    │  客服消息气泡（左、浅色、逐字增长）       │
│                                    ├─────────────────────────────────────────┤
│                                    │  多行输入框                   ［发送］    │
└────────────────────────────────────┴─────────────────────────────────────────┘
```

小于 `768px` 时会话列表默认折叠，页面保留聊天区与输入区；通过顶部“会话”按钮展开侧栏。界面不使用外部图片或字体资源；猫咪像素头像由 CSS/文本符号实现。

## 交互与数据流

### 会话

- 页面启动时创建一个新会话，并在 `localStorage` 保存前端会话元数据：`id`、`title`、`preview`、`messages`。
- `session_id` 使用 `crypto.randomUUID()`；不支持时使用时间戳与随机字符串的降级实现。
- “＋ 新对话”创建并激活空会话；左侧会话卡显示最近用户消息截断摘要。
- 切换会话使用对应的 `session_id` 调用既有后端，因此同进程内可连续多轮；客户端已存消息用于即时重新渲染。

### SSE 发送

1. 用户发送非空文本后立即追加右侧用户气泡与一个空的左侧客服气泡。
2. 以 `fetch` 调用 `/api/chat`，读取 `ReadableStream`，通过 `TextDecoder` 按 SSE 空行分帧。
3. 对 `data: {"delta":"..."}` 解析 JSON，并将 `delta` 追加到当前客服气泡；滚动区域自动跟随底部。
4. 收到 `data: [DONE]` 后结束 loading 状态、更新会话摘要和 `localStorage`。
5. 收到 `data: {"error":...}`、非 2xx 响应或网络错误时，在当前客服气泡显示简洁错误说明；用户可以再次发送。

发送期间，发送按钮禁用以避免同一会话并发流；Enter 发送、Shift+Enter 换行。后端模型尚未发送可见 `delta` 前，输入区显示“客服正在处理…”，不转发或展示上游 reasoning。

## 组件边界

- `App.vue`：持有会话、消息、流状态和 API 调用编排。
- `components/SessionSidebar.vue`：会话列表、新会话按钮、移动端展开状态。
- `components/ChatHeader.vue`：品牌、在线状态、移动端会话按钮。
- `components/MessageBubble.vue`：用户/客服气泡和流式光标。
- `components/ChatComposer.vue`：受控输入、Enter/Shift+Enter 行为和发送状态。
- `api/chatClient.ts`：仅负责 SSE 帧解析和 `/api/chat` 请求；向调用方以回调交付 delta/done/error。
- `types/chat.ts`：前端 `ChatSession`、`ChatMessage`、`ChatRole` 类型。
- `styles/`：设计令牌与像素风全局样式。

## 验证

- 单元测试覆盖 SSE 帧解析：分块到达、多个帧、`[DONE]`、错误事件与无效 JSON。
- 组件测试覆盖：空消息不可发送、输入后追加用户气泡、每个 delta 增长客服气泡、done 后恢复发送、错误可见。
- 手动浏览器验收：打开聊天页，发送问题观察逐字回复；同一会话追问时回复能引用前一轮订单事实；创建第二会话后不会混入第一会话的前端消息。
- 构建验证：`npm run build` 成功；后端 `make test` 继续通过。

## 验收

1. 浏览器中可看到像素风双栏客服页面与会话侧栏。
2. 发送消息后，用户气泡立即出现，客服气泡随 SSE `delta` 增长，完成后输入可再次发送。
3. 同一会话第二次追问能保留并展示前文；新会话的前端消息列表独立。
4. 页面不显示任何工具调用、虚构订单数据或 reasoning 内容。
