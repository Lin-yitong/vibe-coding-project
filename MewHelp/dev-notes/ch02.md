## Task 3：LangChain 业务工具与白名单注册中心（2026-09-13）

- 提供且只注册 `query_order`、`query_product`、`query_logistics`、`query_faq`、`create_ticket` 五个显式 Pydantic schema 的 `@tool`；前三项基于规范化输入返回固定 JSON，避免访问数据库。
- FAQ 和工单工具通过 `configure_business_repositories()` 消费窄 repository。FAQ 返回命中问答 JSON 或“未找到匹配 FAQ。”；工单类型由 schema 固定为“售后”“投诉”“咨询”。
- `ToolRegistry.execute()` 只从白名单取工具，结构校验、schema 错误、超时和最终执行错误均返回无堆栈的 `ToolExecutionResult`。同步 `.invoke()` 被移至线程，超时不重试；仅可重试的执行异常重试一次。
- TDD：先运行 `pytest tests/test_tools.py tests/test_tool_registry.py -v`，确认因 `app.tools` 不存在而收集失败；实现并修正无 async pytest 插件的测试调用后，聚焦测试 9 passed；完整 `pytest -v` 为 55 passed。

## Task 4：单次工具规划和模型回灌编排（2026-09-13）

- `build_tool_calling_model()` 只在规划阶段将普通聊天模型与 `REGISTERED_TOOLS` 绑定一次。`ToolCallingOrchestrator` 接收该规划模型和独立的普通最终模型；因此最终 `PreparedTurn.final_stream()` 只调用后者的 `astream()`，不会再次选择工具。
- 编排先以 `ainvoke()` 取得 `AIMessage.tool_calls`；若有调用，则原样持久化申请，并按模型给定顺序逐项执行、持久化结果、建立同 call id 的 `ToolMessage`。随后一次性将历史、规划消息与所有结果回灌最终模型。无工具调用时不写工具申请/结果，直接以原历史流式回答。
- System Prompt 明确要求：有工具结果时只根据结果回答；无工具结果时不得编造业务事实，并继续按订单号和关键信息追问。
