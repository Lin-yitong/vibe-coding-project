项目目标：
做一个后端服务，用于模拟 6 人局狼人杀。6 个玩家都由 AI/LLM Agent 扮演。第一版不需要真人玩家、不需要 WebSocket、不需要数据库，使用 HTTP API + 内存存储即可。前端后续会调用这些接口展示游戏过程。

游戏规则：

1. 固定 6 人局。
2. 角色配置：

   * 2 个狼人
   * 1 个预言家
   * 1 个女巫
   * 2 个村民
3. 游戏流程：

   * 创建游戏并随机分配身份
   * 第 1 夜开始
   * 狼人选择击杀目标
   * 预言家选择查验目标
   * 女巫选择是否救人、是否毒人
   * 白天公布夜晚死亡情况
   * 存活玩家依次发言
   * 存活玩家投票
   * 最高票玩家出局
   * 判断胜负
   * 如果未结束，进入下一夜
4. 胜利条件：

   * 所有狼人死亡，好人阵营胜利
   * 狼人数量大于等于好人数量，狼人阵营胜利
5. 后端必须作为规则裁判，不能直接相信 Agent 输出。
6. 死亡玩家不能行动、不能发言、不能投票。
7. 女巫只有一瓶解药和一瓶毒药，每瓶只能使用一次。
8. 预言家每晚可以查验一名存活玩家。
9. 狼人每晚只能击杀一名存活玩家。

核心设计：

1. GameService 是业务调度中心，负责创建游戏、推进游戏、保存状态、记录日志。
2. GameEngine 是狼人杀规则引擎，负责状态流转、行动结算、胜负判断。
3. RuleChecker 负责校验行动是否合法。
4. AgentService 负责调用 AI 玩家。
5. 第一版先实现 RandomAgent 或 RuleBasedAgent，确保没有真实 LLM API Key 时也能完整跑通。
6. 预留 LLMPlayer 接口，后续可以接入 OpenAI API 或其他大模型。
7. PromptBuilder 负责构造不同身份视角下的提示词，必须避免上帝视角泄露。
8. 游戏日志分为 public_logs 和 debug_logs：

   * debug_logs 给开发者调试，可以记录角色、Agent 原始输出、规则校验结果。

API 设计：

1. POST /api/games
   创建一局新游戏。
   返回 game_id、当前阶段、玩家列表。
   默认不要暴露角色身份。

2. GET /api/games/{game_id}
   获取当前游戏状态。
   默认不暴露隐藏身份。
   支持 query 参数 debug=true，debug 模式可以返回完整角色信息和 debug_logs。

3. POST /api/games/{game_id}/step
   推进游戏的下一步。
   返回当前阶段、新增 public_logs、是否结束、winner。

4. POST /api/games/{game_id}/run
   自动运行完整局，直到游戏结束。
   返回 winner、完整 public_logs。
   为了避免死循环，请设置最大 step 数，例如 100。

5. GET /api/games/{game_id}/logs
   获取 public_logs。
   支持 debug=true 时返回 debug_logs。

6. DELETE /api/games/{game_id}
   删除一局游戏。
